Working end-to-end

One Gateway.
Multiple AKS regions.

Give one multi-region AKS application one global public IP. AKS Fleet selects the clusters. Application Network keeps Services available across those clusters. The controller creates the regional L7 Gateways and the Azure global entry point.

2. User experience

Apply one file to the Fleet hub

First, deploy the application and its Service to the selected member clusters. Then apply gateway.yaml once to the Fleet hub. No routing resource must be applied to each member cluster.

The only action needed by a user to request a Global Gateway

The file contains the Gateway, HTTPRoutes, and GlobalGatewayPolicy.

kubectl --kubeconfig fleet-hub.yaml apply -f gateway.yaml
gateway.yaml
## Define the public listener for the application.
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  ## Use the same namespace for the Gateway, routes, and policy.
  name: my-app
  namespace: my-app
spec:
  ## Select the global controller and regional Istio Gateways.
  gatewayClassName: global-istio
  ## The controller copies these listeners to every selected cluster.
  listeners:
  - name: https
    protocol: HTTPS
    port: 443
    ## Terminate TLS at each regional L7 Gateway.
    tls:
      mode: Terminate
      certificateRefs:
      - name: my-app-tls
---
## Define the L7 route once. The controller creates the regional copies.
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: my-app
  namespace: my-app
spec:
  ## Attach this route to the global Gateway above.
  parentRefs:
  - name: my-app
  ## Match requests for this DNS name.
  hostnames:
  - app.example.com
  rules:
  ## Send matching requests to this Kubernetes Service.
  - backendRefs:
    - name: my-app
      port: 80
---
## Connect the Gateway to Fleet and Azure.
apiVersion: gateway.glb.azure.io/v1alpha1
kind: GlobalGatewayPolicy
metadata:
  name: my-app
  namespace: my-app
spec:
  ## Select the Gateway that this policy manages.
  targetRef:
    group: gateway.networking.k8s.io
    kind: Gateway
    name: my-app
  fleet:
    ## This placement status is the source of the regional cluster list.
    workloadPlacementRef:
      group: placement.kubernetes-fleet.io
      kind: ClusterResourcePlacement
      name: my-app
  azure:
    ## Create the global Azure resources in this subscription.
    subscriptionID: 00000000-0000-0000-0000-000000000000
    ## This resource group contains only the global load balancer and IP.
    resourceGroup: my-app-networking
    ## Store the global Azure resources in this Azure location.
    location: centralus
Global address

The standard Gateway status contains the public IP.

kubectl get gateway my-app -o jsonpath='{.status.addresses[0].value}'

3. Control plane

The controller builds and maintains the topology

Gateway, HTTPRoute, or policy changes start reconciliation. A periodic check also repairs missed events and external changes.

  1. 1. Watch intentRead the Gateway, attached routes, and policy.
  2. 2. Resolve FleetRead the selected member clusters from placement status.
  3. 3. Validate ServicesConfirm that route backends use the required global Service and waypoint configuration.
  4. 4. Create regional L7Create child Gateways and HTTPRoute copies through Fleet.
  5. 5. Program AzureCreate the global IP, load balancer, probes, and regional backends.
  6. 6. Publish statusWrite the global IP and conditions to the source Gateway.

4. Component responsibilities

Each component has one job

The design separates cluster placement, L7 routing, Service failover, and global region selection.

C

GLB Gateway Controller

Connects Gateway API, Fleet, Application Network, and Azure. It creates regional L7 intent and publishes Gateway status.

F

AKS Fleet

Defines the cluster group. It places the workload and generated Gateway resources on the same members.

N

Application Network

Provides managed Istio Gateway classes and cross-cluster Service discovery. It selects a remote endpoint when needed.

GLB

Azure global load balancer

Provides one anycast public IP. It selects a healthy regional frontend.

L7

Regional Gateway

Applies the copied listeners and HTTPRoutes. It sends traffic to the Application Network Service.

U

Application owner

Defines the workload placement, Gateway, HTTPRoutes, policy, Services, readiness probes, and TLS material.

5. Use cases

Use one endpoint across several failure domains

A global Gateway is useful when one application runs in several AKS regions.

↘

Lower client latency

The anycast IP sends a new connection to a nearby healthy Azure region.

HA

Multi-cluster availability

Traffic can use another regional frontend when one cluster or ingress is unavailable.

S

Service endpoint failover

Traffic can use ready application pods in another member cluster when local pods are unavailable.

DNS

Stable DNS and IP

DNS points to one global IP. Regional cluster changes do not require a DNS change.

↻

Regional maintenance

Drain or replace one regional cluster while other regions continue to serve traffic.

API

One routing API

Application teams use Gateway API. The controller manages the Azure and Fleet resources.
